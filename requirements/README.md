# Requirements Directory

This directory contains Python dependency specifications for building, running,
and testing vLLM across different hardware platforms and use cases.

## File Naming Conventions

- **`.in` files** -- Unpinned (or loosely pinned) dependency specifications.
  These are the human-edited source-of-truth files that list what packages are
  needed, with flexible version constraints. They are portable across
  platforms.

- **`.txt` files** -- Either hand-maintained requirement lists or fully pinned
  lockfiles generated by `uv pip compile` from a corresponding `.in` file.
  Pinned lockfiles contain exact versions of every transitive dependency and
  are tied to a specific platform (typically `x86_64-manylinux_2_28`, Python
  3.12). A comment at the top of each generated file shows the exact command
  used to produce it.

When both a `.in` and `.txt` variant exist for the same name (e.g.,
`test.in` / `test.txt`), the `.in` file is what you edit and the `.txt` file
is regenerated from it. On non-x86_64 platforms, install from the `.in` file
so that `uv` can resolve appropriate packages for the current architecture:

```bash
uv pip install -r requirements/test.in    # resolves for current platform
uv pip install -r requirements/test.txt   # x86_64 only (pinned lockfile)
```

## File Reference

### Core Runtime

| File | Description |
|------|-------------|
| `common.txt` | Shared runtime dependencies used by all platforms. Included via `-r common.txt` by the platform-specific files below. |

### Platform-Specific Runtime

Each of these files includes `common.txt` and adds platform-specific packages
(PyTorch builds, vendor libraries, etc.):

| File | Platform |
|------|----------|
| `cuda.txt` | NVIDIA GPUs (CUDA). Includes FlashInfer, cuDNN, and CUTLASS/QuACK kernels. |
| `cpu.txt` | CPU-only (x86_64, aarch64, s390x, ppc64le, riscv64). |
| `rocm.txt` | AMD GPUs (ROCm). Includes ROCm-specific extras like `conch-triton-kernels` and `amd-quark`. |
| `tpu.txt` | Google TPUs. Includes Ray and `tpu-inference`. |
| `xpu.txt` | Intel GPUs (XPU). Includes `vllm-xpu-kernels`. |

### Build

| File | Description |
|------|-------------|
| `build.txt` | Build-time dependencies for the default (CUDA) build. Mirrored in `pyproject.toml`. |
| `cpu-build.txt` | Build-time dependencies for CPU builds. |
| `rocm-build.txt` | Build-time dependencies for ROCm builds. Includes PyTorch from the ROCm pip index and `amdsmi`. |

### Testing

| File | Description |
|------|-------------|
| `test.in` | Unpinned test dependencies for CUDA. The human-edited source file. |
| `test.txt` | Pinned lockfile generated from `test.in` (x86_64 / CUDA). |
| `rocm-test.in` | Unpinned test dependencies for ROCm. Shares most entries with `test.in` but adds ROCm-specific packages. |
| `rocm-test.txt` | Pinned lockfile generated from `rocm-test.in`. |
| `xpu-test.in` | Unpinned test dependencies for XPU. A smaller, incremental set -- the base image already has `common.txt` and `xpu.txt`. |
| `xpu-test.txt` | Pinned lockfile generated from `xpu-test.in`. |
| `nightly_torch_test.txt` | Test dependencies for nightly PyTorch testing. |

### Development and Tooling

| File | Description |
|------|-------------|
| `lint.txt` | Linting and formatting tools (`pre-commit`). |
| `dev.txt` | Development meta-file that combines `lint.txt` and `test.txt`. |
| `docs.txt` | Documentation build tools (MkDocs and plugins). |

### Optional / Feature-Specific

| File | Description |
|------|-------------|
| `kv_connectors.txt` | Dependencies for KV cache connector backends (`lmcache`, `nixl`, `mooncake-transfer-engine`). |
| `kv_connectors_rocm.txt` | ROCm-specific KV connector dependencies (`lm_eval`). |

## Regenerating Pinned Lockfiles

Pinned `.txt` lockfiles are generated from their `.in` counterparts using
`uv pip compile`. The exact command is recorded in a comment at the top of
each generated file. For example:

```bash
uv pip compile requirements/test.in \
    -o requirements/test.txt \
    --index-strategy unsafe-best-match \
    --torch-backend cu129 \
    --python-platform x86_64-manylinux_2_28 \
    --python-version 3.12
```

Constraints from the corresponding runtime file (e.g., `rocm.txt`) are often
passed via `-c` to keep test dependencies compatible with the installed
runtime packages.

## Dependency Hierarchy

```
common.txt
  |
  +-- cuda.txt      (NVIDIA runtime)
  +-- cpu.txt       (CPU runtime)
  +-- rocm.txt      (AMD runtime)
  +-- tpu.txt       (TPU runtime)
  +-- xpu.txt       (Intel runtime)

test.in  ----------> test.txt          (CUDA tests, pinned)
rocm-test.in ------> rocm-test.txt     (ROCm tests, pinned)
xpu-test.in -------> xpu-test.txt      (XPU tests, pinned)

lint.txt  -+
test.txt  -+--> dev.txt               (development meta-file)
```
